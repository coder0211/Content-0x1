## Quyết định kỹ thuật bổ sung (để agent không bị kẹt)

- Go module path: `github.com/be/acs/api`. Go 1.26. DB access: **pgx v5 + sqlc** (sinh code commit vào repo; dev chạy `go run github.com/sqlc-dev/sqlc/cmd/sqlc generate`). Migrations: **goose** (chạy bằng `go run` hoặc embed trong `cmd/acs migrate`).
- Queue: **asynq** trên Redis. Web: **pnpm**, Vite, React 19, TS strict, Tailwind, shadcn/ui, TanStack Query, Vitest, Playwright.
- Test DB: testcontainers khi có Docker; nếu không có Docker thì test integration tự `t.Skip` — unit test (domain/usecase với fake repo) luôn chạy.
- Docker daemon có thể không chạy trên máy dev → mọi agent phải đảm bảo `go build ./... && go test ./...` và `pnpm build && pnpm test` pass mà không cần Docker.

## Agent 2 — Frontend foundation (web/)

- **Toolchain pinned to stable majors:** Vite 7, TypeScript 5.9, ESLint 9, Tailwind **3.4** (SPEC-05 §2.5 uses `tailwind.config.ts`), Vitest 3, MSW 2, React Router 7 (data router), TanStack Query 5, React 19. Newer majors (TS 7, Tailwind 4, ESLint 10…) are not supported by typescript-eslint/eslint-plugin-boundaries yet.
- **Tailwind theme is replaced, not extended**, for colors, font size, weight, radius, and shadow. Only SPEC-05 tokens exist. Lint (ESLint `no-restricted-syntax` + `scripts/check-forbidden-css.mjs`) additionally bans gradient, blur, `rounded-2xl+`, `shadow-lg+`, non-token text sizes and weights, and `rounded-full` outside `shared/ui`. The `eslint-plugin-tailwindcss` mentioned in SPEC-05 is not used (its Tailwind support lags behind).
- **shadcn/ui components are vendored by hand** into `web/src/shared/ui` (Radix + cva) and restyled to tokens. No `components.json`/CLI, since the current CLI targets Tailwind 4. Toast uses `sonner`.
- **CSRF:** read the `acs_csrf` cookie (matches api `CSRF_COOKIE` default) → header `X-CSRF-Token`, falling back to `csrf_token` from `POST /auth/login`. A wrong password returns `401 INVALID_CREDENTIALS` (matches api). `GET /me` 401 means anonymous; any other 401 → redirect `/login?next=…&reason=expired`.
- **Errors:** mutation errors toast automatically (code → Vietnamese copy in `shared/lib/errors.ts`; opt out with `meta.silentError`). Query errors render inline with `ErrorState`. `ApiError` lives in `shared/kernel` so every layer can branch on `code`.
- **Permission-based navigation:** an extra sidebar item **"Chi phí & ngân sách"** (`/usage`, `usage.view`, module `budget`) satisfies the ACS-010 AC. Settings is visible with `anyOf [user.manage, provider.view, budget.manage, audit.view]`. `PermissionRequirement` supports a single code, all-of arrays, and `{ anyOf }`. Route permission comes from `handle.permission`, and the shell renders `NoPermission` (never a silent hide). Job pages (`/jobs`) have no sidebar entry.
- **Module contract:** each `modules/<m>/index.ts` exports `routes` / `publicRoutes` / `navItems` / `repositories`. `app/modules.ts` and `app/mocks/handlers.ts` hold one line per module and are pre-filled for all 12 modules, so feature agents never edit `app/`. DI is a `RepositoryRegistry` interface augmented per module (`declare module "@/shared/lib/di"`).
- **Boundaries:** `application` and `presentation` may import **other modules only via `index.ts`**. Only `infrastructure` may import `shared/api`. `domain` imports only `shared/kernel`. Tests are exempt.
- **Dependencies preinstalled** to avoid lockfile conflicts between parallel agents: react-hook-form, zod 4, @hookform/resolvers, zustand, @dnd-kit (storyboard drag and drop), Radix primitives. Adding packages requires the orchestrator.
- **Fonts self-hosted** via `@fontsource/be-vietnam-pro` (400/500/600) and `@fontsource/jetbrains-mono` (works on an offline intranet; no Google Fonts CDN).
- **Mock mode:** `pnpm dev:mock` (`.env.mock`, `VITE_API_MOCKING=true`) runs the whole UI on MSW. Seed accounts are `admin|lead|creator|reviewer@acs.local`, password `matkhau123`. Playwright runs against it.
- **`/_design`** is a public route (no login) so the PO can review the style without a backend.
- **Test env on Node ≥ 22:** `src/test/polyfills.ts` replaces Node's experimental `localStorage` and strips jsdom `AbortSignal`s that undici's `Request` rejects (a known jsdom + React Router data-router issue).

## Agent 1 — Backend foundation (api/, root tooling)

- **File storage is its own module `file`** (not part of `asset`): `asset_files` is referenced by brand assets, image references, scene sources, renders and asset versions, so it is a leaf module (`file/usecase/api.go`), and `asset` links versions to file IDs. The `asset` module keeps content assets, versions, approvals and audited downloads.
- **Schema additions to SPEC-03 (in base migrations, not later):** `users.last_failed_login_at` (true 5-failures-per-15-minutes window), `budget_settings.global_monthly_limit/global_alert_thresholds/global_hard_stop` (template for each month's lazily created global budget, OQ-03 $1,000), helper `immutable_unaccent()` for `search_tsv`, extra indexes (`idx_usage_job`, `idx_reservations_job`, `idx_audit_created`, `idx_notifications_user_created`), `set_updated_at` trigger on `ai_providers`.
- **Audit append-only** is enforced by a trigger that blocks UPDATE/DELETE/TRUNCATE for every role, plus `REVOKE` when an `acs_app` role exists (prod). This covers ACS-009 without requiring a separate DB role locally.
- **Seed 0011:** roles + RBAC matrix (kept equal to `kernel.RolePermissions` by a test), budget settings (OQ-03), `fake` provider with default text/image/video/voice models and pricing `fake-2026-10`. Real providers/models/pricing and prompt templates are seeded by their modules in later migrations.
- **Migration numbering:** reserved blocks per module (see `docs/CONVENTIONS.md` §5) so parallel agents never collide.
- **Session/CSRF:** session cookie `acs_session` (HttpOnly, SameSite=Lax, Secure in prod) holds a random 256-bit token; only its SHA-256 is stored. CSRF = synchronizer token stored on the session, mirrored to the readable cookie `acs_csrf` and returned by login; non-GET requests must send it in `X-CSRF-Token` (login exempt). `last_seen_at` is written at most once per minute. Idle 12h / absolute 7d / lockout 5 per 15 min are env-configurable.
- **Login error codes:** wrong e-mail or password → `401 INVALID_CREDENTIALS` (indistinguishable, constant-time); temporary lockout and admin lock → `423 ACCOUNT_LOCKED`; disabled → `403 ACCOUNT_DISABLED`; expired/revoked session → `401 SESSION_EXPIRED`; no cookie → `401 UNAUTHENTICATED`. Admins cannot lock/disable themselves or drop their own admin role. Password minimum length: 10.
- **Malformed path IDs return 404** (they cannot name a resource); unknown JSON fields return `400 VALIDATION_FAILED`.
- **Idempotency:** `httpx.RequireIdempotencyKey` validates the UUID header and hashes `METHOD path\nbody`; de-duplication is done by `job.API.Create` on `(created_by, idempotency_key)`. A missing/invalid key is `400 IDEMPOTENCY_KEY_REQUIRED`.
- **Job → budget coupling** goes through hooks wired in `internal/app/hooks.go` (`OnFinished` → `Budget.Settle`, `OnRetried` → `Budget.Reserve`), because `job` may not import `budget` (SPEC-06 §2.5). Step handlers call `Budget.RecordUsage` themselves.
- **AI ports:** `TextGenerator` and `ImageGenerator` both define `Generate`, so a vendor offering several capabilities exposes one adapter type per capability (see `providers/fake`). `VideoGenerator` gained `Download` (fetch output after polling). `ports.Usage.Units` is keyed by `model_pricing.unit` so budget prices any provider uniformly.
- **Storage:** minio-go (S3-compatible, works with AWS S3) instead of aws-sdk-go-v2; a second client signs URLs for `S3_PUBLIC_ENDPOINT` (browser-facing host). `/files/{id}/complete` downloads the object to a private temp file for ffprobe (no URLs passed to ffprobe, SSRF-safe).
- **Architecture enforcement:** depguard (framework bans per layer) + `internal/archtest` (module dependency table, R4) which runs in `go test ./...`. `go-arch-lint` is not used; archtest replaces it.
- **OpenAPI:** fragments `api/openapi/<module>.yaml` bundled by `tools/openapi-bundle` into `api/openapi.yaml` (OpenAPI 3.1, servers `/api/v1`; health endpoints override to `/`). A test fails when the bundle is stale.
- **Placeholders:** `job, budget, asset, brand, campaign, provider, content` have placeholder `module.go` files that publish the in-memory fakes from `<m>test`, so the server runs end-to-end today; their owners replace `Register`.

## Agent 3 — Job engine

- **Schema:** migration `0020_job_engine.sql` only adds indexes, `ai_job_steps.generation` (bumped on retry so the asynq unique task id `step_id:attempt[:gN]` never collides with an earlier run) and `max_attempts DEFAULT 0` (= engine default per queue: 3, video 5). Base tables stay in 0008.
- **Retry policy:** only `Transient`/`RateLimited` step errors are retried (exponential backoff + jitter); `InvalidRequest`, `ContentPolicy`, `Permanent` and domain errors fail the step at once. A failed step fails the job; its unfinished steps become `cancelled`. `POST /jobs/{id}/retry` re-runs only failed/cancelled/skipped steps; owner may retry codes in `retryableJobCodes` (STEP_FAILED, STEP_TIMEOUT, LEASE_EXPIRED, PROVIDER_WAIT_TIMEOUT, PROVIDER_*), anything else needs admin `{force:true}`. Finished/non-failed → `409 INVALID_STATE_TRANSITION`.
- **Cancel:** sets `cancel_requested`; with no in-flight step the job is cancelled immediately, otherwise the running step finishes and the rest are cancelled. Waiting-provider steps are polled at once and `CancelHandler.OnCancel` (optional, additive) is called. Finished job → 409.
- **Visibility:** `GET /jobs*` returns NOT_FOUND (anti-IDOR) for jobs of other users unless the actor has `provider.view`; cancel/retry require owner or admin.
- **Rate limit (ACS-043):** `job.API.Create` itself enforces 30 creations/min/user (Redis fixed window) for user-initiated jobs (those with an idempotency key) → `429 RATE_LIMITED`. Modules wanting to reject before estimation can mount the middleware shown in `usecase.RateLimitCreate` docs; the ctx marker prevents double counting.
- **Concurrency caps:** Redis semaphore per `provider:model` (limit from `ai_models.concurrency_limit` via Providers API) and per-user video; over cap the step is re-enqueued with delay (event `concurrency_wait`), never failed.
- **Stale uploads:** reconciler calls `Files.PurgeStalePending(24h)` when the Files API is published; no-op otherwise.
- **FE:** `/jobs` and `/jobs/:jobId` have no route permission (everyone sees own jobs; the creator filter/column only shows with `provider.view`). The creator filter offers "Mọi người tạo / Của tôi" (+ `?user=<id>` from URL) because no user-list API is available to this module; creator cells show "Bạn" or a short id — promote to names once a users lookup exists. Public API in `modules/job/index.ts`: `useJob`, `useJobProgress`, `JobProgressPanel` (toast on finish), `jobKeys`, domain helpers.
- **FE mocks:** SSE returns 204 in mock mode, so the client exercises the 3s polling fallback; simulated jobs advance by wall-clock. `createMockJob()` in `modules/job/infrastructure/mocks.ts` lets other modules' mocks back their 202 responses with a real job, but eslint boundaries forbid cross-module infrastructure imports — orchestrator may want to promote it to `shared/api/mock` (or add a boundaries exception for `*/infrastructure/mocks.ts`).
## Agent 4 — AI providers + provider config

- **OQ-01 adapters:** `anthropic` (claude-sonnet-5-5, JSON-schema structured output via `output_config.format`), `openai` (gpt-image-1 generate/edit, non-native aspect ratios by centre-crop), `veo` (Gemini API long-running ops; no cancel → `ErrCancelUnsupported`), `kenburns` (FFmpeg zoompan, cost 0, outputs parked in object storage so any worker can download), `gcp_tts` (vi-VN, SSML marks → word timings; API key or service-account JSON). Shared HTTP/error mapping in `providers/vendorhttp`. Details and price assumptions in `docs/spike-providers.md` (TL must verify live).
- **Registry sync:** the provider module pushes each `ai_providers` row (status, secret_ref, config_json) into the process registry at start-up, immediately after an admin update, and every 30 s in server and worker (runner `provider-registry-sync`) so a disable in the UI reaches the worker without restart. A disabled provider surfaces as `CAPABILITY_NOT_SUPPORTED`.
- **Defaults:** the `fake` models of 0011 remain the defaults so local/CI runs need no key; `ResolveModel` skips models whose adapter is not registered (e.g. fake in production) and falls back to the first usable real model.
- **Pricing immutability:** migration 0071 blocks UPDATE/DELETE of `model_pricing` rows except closing `effective_to`; new prices are added as versions via `POST /settings/models/{id}/pricing`.
- **Secrets:** API never returns key material — only `secret_ref` (env var name) and `secret_configured`.
- **Prompt templates (ACS-038 BE):** creating a version allocates `max(version)+1` under a per-code advisory lock; activating retires the previous active version. Lead/Admin only; reads require `provider.view`.
- **Without DB** (`c.DB == nil`) `provider.Register` still publishes the in-memory fake from `providertest`.
## Agent 5 — Cost & Budget (budget module)

- **Endpoints:** `POST /cost-estimates` (generate.run; generic quote for the studios' cost chip, empty provider/model → default model of the kind), `GET /usage/summary` (usage.view; `group_by=day|campaign|provider|model|user|job_type`, every row split by `cost_source`, totals equal the sum of rows), `GET|PATCH /settings/budgets` (global monthly template + per-job limits per category + campaign budget list; PATCH needs budget.manage, audited), `GET|PUT /campaigns/{id}/budget` (PUT needs budget.manage, audited).
- **Estimators** are shared item builders in `budget/usecase/estimators.go` (`TextItems`, `ImageItems`, `VideoItems`) so every studio prices work identically: text = input tokens from prompt runes + overhead, output = `max_output_tokens` (default 1024); image = count × unit `image_<size>_<quality>`; video = clip seconds × `video_second_<res>` + TTS chars + optional script tokens + a 0-cost `render` line. Any missing price → `503 PRICING_MISSING`.
- **Reserve** runs in the caller's transaction, locks global (lazily created for the current month from `budget_settings`) then campaign (`FOR UPDATE`), is idempotent per job, checks per-job limit (`429 JOB_BUDGET_EXCEEDED` with estimate/limit details; Lead/Admin override, audited), then hard stop: global requires Admin override, campaign Lead/Admin; overrides are audited. Concurrency proven by an in-memory locked unit test and a pg test (skips without Docker).
- **Settle/Release** share one idempotent path: held reservations are released, unsettled usage (`ai_usage_records.settled_at IS NULL`, new column in 0030) moves into `spent_amount`, and `ai_jobs.cost_actual` = sum of the job's usage records; `cost_source` = provider_reported only if all records are, `estimated` if any is, else `calculated`. Usage without pricing is still stored (cost 0, `estimated`) and the job is flagged `needs_reconciliation`.
- **Alerts** (80/100% or configured thresholds) fire once per budget period (`budgets.alerts_sent`), one in-app notification (highest threshold reached) to users with `budget.manage`, and an e-mail queued in `budget_alert_emails` within the same tx; a worker runner (`budget-alert-mail`, every 30s, ≤5 attempts) delivers via the platform mailer, so rolled-back reservations never send mail.
- **FE:** `/usage` (summary tables + plain SVG bars, cost_source split) and `/usage/budgets` (ACS-093 settings + campaign budget dialog). `useEstimate`, `EstimateBudgetBanner`, `CampaignBudgetDialog` are exported from `modules/budget/index.ts`.
## Agent 6 — Brand, Product, Campaign

- **Brand versioning (ACS-020):** every PATCH that changes the profile creates a new `brand_versions` row; a PATCH with an unchanged profile is a no-op (no new version). `expected_version_no` is required and a stale value → `409 VERSION_CONFLICT`. Colours must be `#RRGGBB`; a word cannot be both preferred and forbidden.
- **Music licence (ACS-023):** licences live on `brand_assets.license_json` (migration 0040) rather than `asset_files.license_json`, because the brand module may not write the file module's table. A DB CHECK requires `{source, license_type}` for music. `BrandAPI.RequireLicensedMusic` (additive) is what the video module calls; it returns `VALIDATION_FAILED {music_asset_id: license_required}` for missing/expired licences. `BrandAsset.LicenseValid` added (additive).
- **Offers (ACS-022):** offer status (active/expired/upcoming) is computed against the Vietnam business day (UTC+7). `GetBrandContext` drops expired/upcoming offers and unverified proof; the UI flags expired offers.
- **Content plan (ACS-037):** the `content_plan` job writes a *proposal* (`campaigns.content_plan_proposal`, migration 0050) through `CampaignAPI.SaveContentPlanProposal`. A user edits it and approves with `PUT /campaigns/{id}/plan`, which stores `content_plan` (+ approved_by/at) and clears the proposal. A proposal never overwrites an approved plan. Plan items have stable ids (`item-N`) and a `done` flag; the Overview tab shows the approved plan as a checklist.
- **Campaign UI (ACS-026):** the brief wizard is a full page `/campaigns/new` (2 steps: header → brief), not a dialog, because the brief is long. The verified offer is picked only from active offers of the selected products. Status changes are buttons for the allowed `next_statuses` (from the API); `completed` and `archived` ask for confirmation. "Tạo mới" links go to `/content|/images|/videos?campaign_id=<id>`, and plan-item links add `&plan_item_id=<item id>`. Studios should read these query params.
- **Campaign list columns:** asset counts per type and cost are not in the campaign API yet (SPEC-04 mentions them for `GET /campaigns/{id}`). The list shows the requested outputs from the brief instead; the detail tabs list assets through `GET /assets?campaign_id&type`. The remaining budget in the header is left to the budget module.
- **Mocks shared with other modules:** `web/src/modules/campaign/infrastructure/mocks.ts` also mocks `POST /campaigns/{id}/plan-generations` (content module), `GET /jobs/{id}` (only for job ids it created; anything else falls through), and `GET /assets?campaign_id=…` (only for its own campaign ids; anything else falls through). Campaign handlers are registered before content/library/job, so at merge time the orchestrator may drop these three handlers once those modules mock the endpoints.
- **Shared UI note:** `Button asChild` crashes because `Button` always renders a `null` spinner slot next to the child, which Radix `Slot` rejects. The campaign module renders links with `buttonVariants(...)` instead. Promote a fix in `shared/ui/button.tsx` (render `children` alone when `asChild`).
## Agent 10 — Asset, Review, Library, Dashboard, Ops UI, Deploy

- **Migration 0060** adds `content_assets.usage_rights` (FR-AST-06 free-text note) and `content_assets.submitted_at` (review queue is ordered oldest submission first; dashboard counters), plus keyset/queue/creator indexes. `search_tsv` = title (A) + version body text (B) + tags (C) through `immutable_unaccent`, recomputed on every new version / title / tag change; queries use prefix `to_tsquery('simple', …)` built in `asset/domain`.
- **Review notifications** go through `ports.Notifier` (wired to the audit API, which owns `notifications`): submit → all users with `asset.review`; approve / request-changes → the creator. Self-approval is rejected unless the actor is Admin; request-changes requires a comment; posters require `checklist.typography_checked=true` on submit.
- **Approved asset + new version → draft** (needs re-review). Restore creates a new version copied from the old one (history is never rewritten). Stale `base_version_no` → `409 VERSION_CONFLICT`.
- **Download (ACS-084):** only approved assets may be downloaded by Content Creators (draft/pending → 403); Lead/Admin may download any status. Every signed URL is audited.
- **AssetAPI additive changes:** `AssetView.UsageRights`, `AssetView.SubmittedAt`, `API.CountByStatus` (used by dashboard).
- **Dashboard (ACS-095)** reads counters read-only with its own sqlc queries over `campaigns`, `ai_jobs`, `ai_usage_records`, `budgets/budget_settings` (a reporting read model; no writes, no cross-module usecase calls besides `asset.CountByStatus`). Widgets the user may not see are `null`: queue size needs `asset.review`, cost needs `usage.view`; jobs are the user's own unless `provider.view`.
- **FE:** the library module is the single asset API client; the review module reuses its hooks/renderer, and all asset + review MSW handlers live in `library/infrastructure/mocks.ts` (review mocks stay empty to avoid duplicate handlers). Text diff is word-level LCS with whitespace gaps folded into one edit. Settings consumes identity (`/users`), audit (`/audit-logs`) and provider (`/settings/providers|models|pricing`) endpoints per SPEC-04; pricing versions are append-only in the UI (a new version closes the current one), and provider forms reject secret-looking values (only `secret_ref` names are accepted).
- **FE `Button asChild` + `Link`** crashes Radix Slot (Button renders a `null` spinner sibling), so links styled as buttons use `<Link className={buttonVariants(...)}>`.
- **Ops:** Prometheus/Grafana under the `observability` compose profile in `deploy/staging`; alerts: job failure rate, outbox lag, video backlog, budget 80/100%, API down/latency. Staging deploy = GitHub Actions over SSH with placeholder secrets; nginx terminates HTTPS and disables buffering for SSE. Backups: nightly `pg_dump` custom format + MinIO mirror (`deploy/backup`), runbooks in `docs/runbooks/`.
## Agent 7 — Content Studio (content module, api + web)

- **The content module owns no tables.** Generated variants are stored as `asset_type=content` assets and versions through `asset.API`, one asset per variant, with `generated_by_job_id`, brand version and provenance (provider, model, prompt template code and version) in `content_json.provenance`. Content plans are stored through `campaign.API.SaveContentPlanProposal`, and approval stays in the campaign module.
- **Step types** (text queue, 120s timeout): `content_generation`, `content_rewrite`, `content_transform`, `content_plan`, `content_image_prompt_suggest`. All writes for a step share one transaction, so a retry never leaves part of the variant set behind.
- **Rewrite** adds a new version to the same asset. **Transform** creates a new asset with `source_asset_id`. A transform to `video_script` adds `scenes` to `content_json`, and `GetVideoScript` returns them along with the body as the script (or the joined scene narrations when the body is empty).
- **Prompt templates** live in code (`usecase/prompt/templates.go`). Migration 0080 is generated from that file by `go test ./internal/modules/content/usecase/prompt -update`, so the seed and the code cannot drift. At runtime the active template comes from `provider.API.ActivePromptTemplate`, with the built-in v1 used when none is found. User data is wrapped in `<user_data>` as JSON with `<`/`>` escaped, so the data can never close the tag (injection-safe), and the system prompt forbids prices or offers that are not in the facts. Golden snapshot tests cover all 7 templates.
- **Checks (ACS-036)** run after generation and after every rewrite or transform. They are warnings only and never block a save. `forbidden_word` matches whole words and phrases, ignoring case and extra whitespace. Diacritics are kept, because in Vietnamese they change the meaning. `unverified_claim` is raised for any money amount or percentage not present in the brief, campaign or product facts. Warnings are stored in `content_json.warnings`. The FE re-runs the same checks on edit, so a warning disappears as soon as the text is edited out.
- **Public API additions** (`content/usecase/api.go`): `StartContentPlan`, `SuggestImagePrompts`, `JobAccepted`, `PlanInput`, `ImagePromptInput`. Endpoints: `POST /content/generations`, `POST /content/{assetId}/rewrites`, `POST /content/{assetId}/transforms`, `POST /campaigns/{id}/plan-generations`, `POST /images/prompt-suggestions` (all return 202 and require Idempotency-Key).
- **FE:** TipTap is not installed, so the editor is a structured form (title, hook, body textarea, CTA, hashtags). ## Agent 8 — Image Studio (api/internal/modules/image, web/src/modules/image)

- **Read model `image_batches` (migration 0090)**: one row per request ("đợt tạo") linking job → asset/version. Deliberately no FKs to `ai_jobs`/`content_assets`/`campaigns` (other modules' tables); only `created_by → users`. ## Agent 9 — Video Studio (api/internal/modules/video, web/src/modules/video)

- **Data model:** `video_projects` (0100) keyed by the `content_assets` id holds settings (preset, size, target duration, source, voice/subtitle/music), the last voice-over/subtitle tracks (with input fingerprints) and the latest QC-passed output. `video_scenes` gains provider tracking + thumbnail (0101) and soft delete with a partial unique index on live sequence numbers (0103), because past job steps reference removed scenes. Prompt templates `video.script` / `video.storyboard` are seeded in 0102 (built-in fallbacks in code).
- **Presets (OQ-07):** `social_vertical` 9:16 1080×1920, `square` 1:1 1080×1080, `landscape` 16:9 1920×1080, 30 fps, H.264/AAC, `1080p` only. Target duration 4–60 s (default 20); storyboard normalised to ≤ 10 scenes of 2–8 s (500 ms steps) summing to the target (~5 s per scene: 20 s → 4 scenes).
- **Timeline:** scenes are joined with a 300 ms `xfade`; voice segments and subtitle cues are placed on the shortened timeline (start_i = Σd − i·300 ms) so they stay aligned; cues never overlap and stop before the next cross-fade. QC duration expectation uses the same total (±0.5 s).
- **DAGs:** `video_storyboard` = script → storyboard. `video_production` / `video_scene_regenerate` / `video_render` = parallel `scene_generation:<n>` (only scenes not ready, or the forced one) + `voiceover_generation` → `subtitle_generation` → `video_render` (depends on all of them) → `quality_check` → `asset_publish_ready`. Voice-over/subtitles are only (re)made when their input fingerprint changed, so re-render and regenerate add no TTS cost. A forced scene step remembers `base_attempt`, so a retry after it succeeded reuses the new clip (1 usage record per regeneration).
- **Quality check** re-renders once inside the `quality_check` step (not a job retry), then fails permanently with `VIDEO_QUALITY_CHECK_FAILED`; the asset gets no new version.
- **Budget gate:** per-job limit checked with `Budget.Limits` before any job is created → `429 JOB_BUDGET_EXCEEDED` with `{estimate, per_job_limit}`; `budget_override` only for Lead/Admin (403 otherwise), stored on `JobSpec.BudgetOverrideBy`, passed to `Budget.Reserve` and audited as `budget.override` in the same transaction. Ready scenes are not counted in estimates.
- **Fallbacks:** provider code `kenburns` (OQ-01) renders still-image clips at zero cost; with `EnableFakeProviders` the `fake` video provider's placeholder bytes fall back to a Ken Burns clip when normalisation fails, so local/CI runs produce a playable MP4.
- **New error codes** (registered in the video HTTP adapter): `MUSIC_NOT_LICENSED` 422 (OQ-04, checked at create/render and again in the render step), `VIDEO_JOB_IN_PROGRESS` 409 (edits/new jobs while a job runs), `VIDEO_QUALITY_CHECK_FAILED` 422. `web/src/shared/lib/errors.ts` has no Vietnamese copy for them yet (the server message is shown) — orchestrator may add them.
- **API additions to SPEC-04 §2.6:** `GET /videos` (list, `?campaign_id=`, cursor). Responses include `stage` (storyboarding | editing | producing | ready | failed), `limits`, `current_job` with steps, signed preview/thumbnail/output URLs (≤ 15 min). Video publishes no `usecase.API` (no module depends on it).
- **Ports (additive):** `ports.RenderSpec` gained `ClipDurationsMs`, `VoiceSegments`, `FontsDir`; new `ports.VoiceSegment`. `platform/ffmpeg` builds argument vectors only (no shell), refuses option-like source paths and subtitle/font paths containing filter-graph metacharacters (instead of escaping them); real-ffmpeg tests skip when ffmpeg is missing.
- **Render image:** `deploy/Dockerfile.render` (ffmpeg + libass + Noto fonts, `VIDEO_FONTS_DIR=/usr/share/fonts/noto`, queues `video,render`) and compose service `render-worker` (profile `app`, 2 CPU / 2 GB, tmpfs work dir); the generic compose `worker` now consumes `text,image,maintenance`. `VIDEO_FONTS_DIR` is read in `video/module.go` via `os.Getenv` (config package is not ours) — orchestrator may move it into `config.FFmpeg`.
- **FE:** `/videos` = step 1 form (+ `?campaign_id=`, `?script_from_asset_id=`) and recent list; `/videos/:assetId` = studio layout (brief 320 | canvas with tabs Storyboard/Sản xuất | inspector 300). Storyboard uses @dnd-kit plus up/down buttons (keyboard/a11y); "Sản xuất video" is disabled with explicit reasons (limits, unsaved edits, over per-job limit; Lead/Admin tick an override checkbox). Polling every 3 s while a job runs (the job module's SSE hook is not used to avoid a hard dependency). "Gửi duyệt" calls `POST /assets/{id}/submit-review` (asset module, ACS-080); brands/music come from `/brands` and `/brands/{id}/assets` — `video/infrastructure/mocks.ts` answers those only as fallbacks. Mock mode simulates Flow C; a scene whose visual prompt contains `[lỗi]` fails, to demo partial failure + "Tạo lại cảnh".
